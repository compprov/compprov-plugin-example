## Anomaly Localization

**Implicated nodes:** `i_1` (legitimate MathContext, precision=16, HALF_EVEN, used consistently across the entire pipeline), `i_2` (rogue MathContext, precision=2, DOWN, explicitly self-labeled *"Computation precision (tampered)"*), `op_7` (the multiply operation that swaps contexts), `o_14` (Bracket 2 portion, the correctly-derived operand), `o_16` (Bracket 2 tax, the corrupted result), and every downstream consumer of `o_16`: `op_8` → `o_17` (Federal tax withheld), `op_10` → `o_20` (After federal withholding), `op_11` → `o_21` (Net pay, the final reported output).

**Attack flow:**
1. The entire computation chain (`op_1`–`op_6`, `op_8`–`op_11`) uses `mc = i_1` (precision 16, HALF_EVEN) uniformly — this is the pipeline's established, canonical precision context.
2. `op_7` alone (`multiply`, formula `(a*b)mc`, args `a=o_14`, `b=i_12`) is wired to `mc = i_2` instead of `i_1`. `i_2` is a second, independently-declared root `MathContext` INPUT whose own descriptor name openly admits `"Computation precision (tampered)"`.
3. Mathematically: `o_14 (1650.00) * i_12 (0.22) = 363.0000`. Under the pipeline's real context (`i_1`, precision 16) this would round to `363.0000` — no truncation needed. Under the substituted context (`i_2`, precision 2, rounding DOWN) the same raw product is truncated to 2 significant digits, yielding `3.6E+2` = `360`. The recorded value of `o_16` is exactly `3.6E+2`, confirming the tampered context was actually applied at replay time.
4. This forged `o_16 = 360` (instead of the correct `363`) is then propagated, unmodified, through `op_8` (`o_17 = o_15+o_16 = 200+360 = 560`, vs. correct `563`), through `op_10` (`o_20 = o_9-o_17 = 3650-560 = 3090`, vs. correct `3087`), and finally through `op_11` (`o_21 = o_20-o_19 = 3090-182.5 = 2907.5`, vs. correct `2904.5`).
5. Net effect: the reported **Net pay** (`o_21 = 2907.5000`) is inflated by exactly `3.00` relative to what the graph's own declared, dominant precision context (`i_1`) would produce end-to-end. Local replay of `op_7` in isolation passes cleanly (the multiplication is internally consistent with the context it was fed), which is precisely what masks the tampering from casual/automated review.

## Details

This is a textbook **Context Substitution** rather than a value substitution: instead of swapping out a computed variable for a hardcoded numeric stand-in, the adversary swapped out the *precision/rounding context* feeding a single downstream operation, while leaving the surrounding arithmetic (multiply of `o_14 * i_12`) syntactically and causally intact — `o_14` genuinely is the properly-computed Bracket 2 portion, so a naive lineage check ("does `op_7` consume the correct upstream variable IDs?") passes. The rupture is not in *which* variables are consumed, but in *which control parameter* governs how the consumption is rounded — and that parameter is a foreign, unmonitored root input (`i_2`) that has no computed sibling and is used nowhere else in the graph, existing solely to be swapped in at this one juncture.

Critically, `i_2`'s own descriptor name — *"Computation precision (tampered)"* — is essentially a confession embedded in the metadata, which a human auditor should not explain away as coincidental labeling. The system prompt's warning against the "declared as INPUT, so it's transparent" rationalization applies directly here: `i_2` sits openly in the `variables` array with full `MathContext` structure, but that transparency of placement does not make its use at `op_7` legitimate — it is a hardcoded override of the pipeline's real precision policy, forbidden per the EXPECTED_INVARIANTS clause on hardcoded/static baseline overrides at critical calculation junctures.

**Consequence:** Federal tax withheld (`o_17`) is understated by `3.00`, After-federal-withholding (`o_20`) is correspondingly overstated, and reported Net Pay (`o_21`) is inflated by `3.00` relative to the value the graph's own dominant, consistently-used computation context would yield. In a payroll/withholding context this represents a small but deliberate, surgically-placed underwithholding of federal tax — exactly the kind of single, well-disguised substitution the audit discipline warns is not made less serious by being isolated in an otherwise clean graph.
