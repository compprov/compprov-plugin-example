## Details

This is a textbook instance of the "Origin ID / Hash Aliasing" mechanism named in the attack-vector definition: the same logical entity ("refractive index of air") is re-entered under a different `track.id` (`i_82`) that bypasses the lineage of the computed entity (`o_81`). It slips past naive/local replay checks for two reasons: (a) each individual operation in the environmental-correction chain replays correctly in isolation — the Wexler/Sellmeier/Birch-Downs arithmetic is internally self-consistent and numerically plausible, so a step-by-step audit of `op_1`…`op_47` finds nothing wrong; and (b) `i_82`'s value is close enough to the true computed `o_81` (rounded to the 7th decimal) that a coarse sanity check ("does the wavelength correction look physically reasonable?") also passes. Only a full forward-reachability trace from every root to the *true* terminal output — exactly what this audit performed — reveals that `o_81` never reaches `o_97`, and that the number actually driving the reported gauge-block deviation is an unaudited substitute value with no operational provenance.
