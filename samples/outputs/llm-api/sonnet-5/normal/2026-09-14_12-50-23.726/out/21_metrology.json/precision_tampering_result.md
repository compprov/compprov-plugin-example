## Details

**Mechanism:** This is a textbook instance of "downcasting a precise decimal type to double mid-pipeline" as defined in the attack vector. It passes casual/automated checks because (a) the operation is not duplicated or renamed to disguise itself — it is transparently labeled `Exp_double` — and (b) all surrounding operations still correctly declare and honor `mc`, so a naive scan for "missing MathContext" arguments would need to specifically flag this one outlier among 56 operations, which a purely structural/exact-match heuristic could miss if it isn't checking argument-key completeness op-by-op.

**Materiality assessment:** I explicitly recomputed the propagation of this precision loss. A double's relative error (~1e-16) applied to `svp` (≈2339 Pa) yields an absolute error on the order of 1e-13 Pa. This propagates (attenuated further) through `pv` (≈1175 Pa), `N_v` (≈-4.35 ×10⁻⁸), `N_total` (≈27175.55 ×10⁻⁸), `n` (≈1.0002717...), and ultimately into `deltaL` (≈2.312 nm) at a magnitude many orders of magnitude smaller than the least-significant reported digit. Critically, the *input* measurements themselves (`h` = 0.50, only 2 significant figures; `T_air` = 20.00, 4 sig figs) impose a measurement-uncertainty floor vastly coarser than anything double-precision truncation could erode. Thus, unlike a cyclic salami-slicing scheme, this is a single, non-repeating execution (one calibration run), and the deltas from this operation do not accumulate toward any beneficiary — they are simply lost in noise below the metrologically meaningful precision of the report.

**Conclusion:** This is a genuine, confirmed structural violation of the invariant "rounding/precision context must be explicit and consistently bounded" — `op_9` is provably the sole operation lacking an `mc` argument, breaking the uniform 34-digit precision guarantee that governs every other node in the graph. However, per the audit invariants, an isolated, non-cyclic, transparently-named deviation with demonstrated negligible material impact on the final reported value does not constitute a severe or confirmed exploit — it is flagged as a real but low-to-moderate materiality precision-consistency defect warranting remediation (e.g., replacing `Exp_double` with an arbitrary-precision exponential routine bound to `mc`), not a confirmed high-severity tampering event.
