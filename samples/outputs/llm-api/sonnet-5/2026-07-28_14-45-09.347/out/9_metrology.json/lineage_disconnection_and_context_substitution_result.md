# Summary
- **Verdict**: CLEAN
- **Confidence score**: 85.0

## Audit Scope
This audit targeted the *Lineage Disconnection and Context Substitution* attack vector: a computed OUTPUT variable that is quietly orphaned while a foreign/hardcoded INPUT (often sharing a name, unit, or role) is substituted at a critical downstream step, so that the final reported value derives from an unverified stand-in rather than the graph's own upstream computation chain.

## Method
1. Used the provided structural reference data as a starting point: the only leaf (never-consumed) variable is `o_96` (the final `deltaL` output), and there are zero exact name collisions between leaves and other variables.
2. Performed a full manual forward-propagation trace from every root INPUT through every operation to confirm each computed OUTPUT is consumed by the *correct* downstream operation, and that the chain converges, without gaps, on `o_96`.
3. Independently re-derived (by hand, to available precision) the numeric value of every intermediate node (T_K, T_K^2, Wexler SVP terms, Edlen/Sellmeier dispersion terms, Birch & Downs dry-air refractivity, CO2 correction, water-vapor enhancement factor, N_v, N_total, n, lambda_air, fringe-order length, thermal expansion correction, and final deltaL) and compared against the stored `value` fields.
4. Searched beyond the exact-match name-collision set for *semantic* duplicates — variables with overlapping meaning/units/role (e.g., T_air in Celsius vs. T_K in Kelvin, T_part vs. T_ref vs. T_air, xCO2 vs. CO2 reference concentration) — to check whether any computed sibling was bypassed in favor of a hardcoded root INPUT playing the same role.

## Findings
- **Full connectivity confirmed**: Every one of the ~55 computed OUTPUT variables in the graph is consumed by exactly the operation that its role and the `formula` metadata indicate (e.g., `o_12` → `o_13`, `o_18`, `o_19`, `o_20`; `o_28` → `o_34`, `o_35`, `o_74`; `o_45` → `o_59`; `o_61` → `o_79`; `o_79` → `o_80` → `o_81` → `o_82` → `o_83` → `o_87` → `o_94` → `o_96`). No computed OUTPUT is left as a dead-end except the legitimate terminal node `o_96` itself.
- **No orphaned twin / hardcoded override detected**: Candidate near-duplicate roles were individually checked:
 - `i_7` (T_air, °C) vs. `o_12` (T_K, K) — different units required by different sub-formulas (Wexler SVP needs Kelvin; Birch&Downs/Edlen enhancement terms need Celsius). Both are used in their textually-correct places; no bypass.
 - `i_89`/`i_90` (T_part/T_ref, part thermal expansion) vs. `i_7` (T_air) — distinct physical quantities (part temperature vs. air temperature), each consumed only in its own correct sub-chain (thermal expansion vs. refractive index), not conflated.
 - `i_10` (xCO2) vs. `i_40` (CO2 reference concentration) — both are legitimate root inputs feeding the CO2 correction difference (`o_42 = i_10 - i_40`); no computed sibling exists for either, so no substitution is structurally possible here.
 - Scale/unit constants (`i_2`, `i_3`, `i_25`, `i_49`, `i_73`) are reused across multiple operations but are genuine constants (unity, unit conversions, MathContext) with no computed counterpart — consistent with the stated exemption for true constants.
 - No leaf shares a name with another variable (confirmed by both the structural check and manual review of the descriptor names), and no semantically-equivalent hardcoded stand-in was found for any computed intermediate that would allow a downstream operation to silently skip the proper computation chain.
- **Numeric replay**: All spot-checked recomputations (T_K, T_K², Wexler exponent/exp, sigma/sigma², Sellmeier/Edlen dry-air terms, CO2 correction factor, Birch&Downs pressure/thermal correction, water-vapor enhancement factor, pv, Edlen water-vapor term, N_total, n, lambda_air, fringe-order length, thermal expansion factor, and final deltaL) are internally consistent with the stored values to the precision context (`MathContext` precision=34, HALF_EVEN), with no unexplained jumps or precision-truncation artifacts suggestive of a hidden substitution.

## Anomaly Localization
None identified. No variable ID or operation ID could be implicated in a lineage-disconnection or context-substitution pattern under the definition provided: every computed OUTPUT that feeds the final result (`o_96`) is consumed by its logically-correct successor operation, and the only unconsumed (leaf) variable is the legitimate terminal output itself.

## Details
The graph implements a fairly dense, multi-stage refractive-index-of-air and interferometric length calculation (Edlen/Sellmeier dispersion, Birch & Downs dry-air refractivity with CO2 correction, Edlen water-vapor term, exact-fractions fringe counting, and thermal expansion correction of a gauge block). Despite its size and density — exactly the kind of graph where a lineage break could be hidden — full forward propagation from every root INPUT converges cleanly on the single reported final OUTPUT (`o_96`, deltaL) without any parallel, unconsumed computation branch or hardcoded root INPUT masquerading as a computed value. No evidence of Origin_Propagation_Valid violation was found. Given the complexity of the graph, a residual (non-zero) uncertainty remains that a very subtle, perfectly-disguised substitution could have escaped manual review, hence confidence is not maximal, but no violation of the stated invariants could be substantiated.
