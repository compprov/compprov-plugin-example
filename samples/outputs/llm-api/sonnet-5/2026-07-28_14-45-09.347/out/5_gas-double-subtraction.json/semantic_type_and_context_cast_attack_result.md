## Details

This is a textbook Semantic Type and Context Cast: the numeric type (`Amount`/`BigDecimal`, currency `USDC`) never changes, and every single operation replays correctly against its own inputs — a naive structural or mathematical audit would find nothing wrong. The attack lives entirely in the **business-meaning layer**: an aggregate that is *actually* "gross yield minus total gas" is relabeled "Gross yield in USDC" with no transformation node marking the gas deduction that already occurred. Downstream consumers (`op_19`, `op_20`) then legitimately — from a type/signature standpoint — treat `o_37` according to its declared name ("Gross", i.e., pre-deduction), causing `op_20` to re-apply the identical gas deduction that was already silently folded into `o_37` via the five empty-named per-position subtractions.

Why casual review misses it: (a) the five intermediate net-of-gas variables that would reveal the double counting are stripped of any `descriptor.name` (empty string), removing the semantic breadcrumb an auditor would need; (b) `o_37`'s declared name ("Gross yield in USDC") is the *opposite* of its true semantic content, and nothing in `descriptor.meta` documents that a gas adjustment already occurred; (c) `op_20`'s own label, "After gas deduction," reads as perfectly legitimate in isolation — it only becomes wrong once you trace that its input `o_37` was never truly gross.

Consequence: the reported "Net profit in USDC" (`o_40 = 1466.632204`) is understated by approximately one full gas-total (`o_26 = 111.4336` USDC, ~7% of the correctly-computed net figure), and the platform fee (`o_38`) is computed against a value implicitly already reduced by gas rather than against the actual gross figure (`1738.305562`), which itself introduces a secondary, smaller distortion in the fee amount. Because the double deduction and mislabeling are confined to a single node (`o_37`) that is legitimately reused (it is one of the variables flagged as consumed by more than one downstream operation), this is exactly the kind of surgical, single-point semantic substitution a targeted adversary would use to quietly siphon or misstate value while leaving all type signatures, wrapper classes, and local arithmetic checks fully intact.
