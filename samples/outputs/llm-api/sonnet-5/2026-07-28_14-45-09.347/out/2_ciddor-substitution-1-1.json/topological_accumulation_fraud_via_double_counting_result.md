## Details

**Mechanism:** This is the "Origin ID / Hash Aliasing" variant of the attack family: the same logical entity ("refractive index of air used for this calibration") is represented by two different `track.id`s. One (`o_81`) is the fully derived, defensible value that would satisfy an auditor skimming the DAG for the Ciddor/Birch-Downs computation \u2014 it exists, it's structurally correct, and it is even tagged as an `OUTPUT`, implying it is a reportable quantity. The other (`i_82`) is a bare, unexplained root `INPUT` with no `meta` provenance (no source, no report reference, unlike `i_4`/`i_5`/`i_6`/`i_89` which all carry `report`/`source` metadata), and it is this second value that actually drives the terminal output. A local, per-node replay check ("does `op_48`'s output match `i_6/i_82` under MathContext `i_1`?") passes trivially, because the arithmetic of each individual operation is internally consistent \u2014 the fraud is purely topological: the wrong upstream node was wired into the downstream consumer, and the graph's density (98 operations across atmospheric, dispersion, and interferometric domains) buries this single substituted edge.

This matches the described attack surface even though it manifests as a **substitution** rather than a literal duplicate-addend: instead of routing one root value into an aggregator twice, the adversary routes the *validated computed* value into a discarded sink while quietly feeding a *different, unaudited* value with the same name into the live path that reaches the terminal output. The net effect on the reportable metric is the same class of harm the invariants target: the reported result (`S_reported` = `o_97`) does not correspond to the deduplicated, fully-traced computation (`S_dedup` via `o_81`) that the graph's own topology purports to support.

**Quantified impact:** `i_82 - o_81 \u2248 4.445\times10^{-8}` (relative). Propagated through `o_83 \u2192 o_84 \u2192 o_88 \u2192 o_95 \u2192 o_97`, this shifts the 7 mm nominal length by roughly `7{,}000{,}000\ \text{nm} \times 4.445\times10^{-8} \approx 0.31\ \text{nm}`. Against a reported `deltaL` of only `2.001079747134860745068631984` nm, this is an approximately **15% distortion of the reported calibration deviation** \u2014 highly material for a national-metrology-grade (NRC) gauge block certification where the whole point of the exercise is sub-nanometer traceability. The elaborate, correct Ciddor/Birch-Downs chain (`op_1`\u2013`op_47`) gives the false appearance that the certified refractive index (and therefore the certified length) was derived from first principles from traceable inputs (`T_air`, `P_air`, `h`, `xCO2`, wavelengths with report/date metadata), when in fact the number that determines the certified result was silently swapped for an unsourced, rounded stand-in.

**Why this evades casual/automated review:** exact-string duplicate-ID and duplicate-name detectors would flag `o_81`/`i_82` only as "same name, different id" (which the structural reference data does surface) \u2014 but a naive check stops there, treating it as a harmless leaf/output pair. It takes explicit forward-tracing from every root to the true terminal output (`o_97`) to notice that the *validated* branch (`o_81`) never reaches the terminal, while the *unvalidated* branch (`i_82`) does \u2014 exactly the kind of global-overlap blind spot the audit brief warns local replay cannot catch.
