The properly derived refractive index is a dead end; the number that actually drives the certified output is an unaudited constant.

## Details

**Mechanism:** This is textbook Intermediate Context Hijacking as defined by the attack vector. Local replay of every single operation passes: `op_47`'s add is arithmetically correct given its inputs, `op_48`'s divide is arithmetically correct given *its* inputs (`i_6 / i_82`), and every other operation in the graph checks out. A naive replay/verification tool that only checks "does each operation's output equal f(its declared inputs)" will find zero discrepancies. The rupture is invisible at the operation level — it only appears when tracing whether the value consumed at `op_48` actually originates from the graph's own upstream computation chain for that quantity, versus being an independently injected literal that merely approximates it.

**Why it evades casual/naive checks:**
- `i_82` is declared as a normal root `INPUT` with a `valueClass` of `BigDecimal`, indistinguishable in form from any other legitimate calibration constant (e.g., Sellmeier coefficients, Wexler coefficients) elsewhere in the graph.
- Its value (`1.0002718`) is numerically very close to the correctly computed `o_81` (`1.000271755...`), differing only past the 6th decimal — close enough to survive a sanity/plausibility check, but representing a real, unaudited, unexplained truncation that discards the actual measured atmospheric conditions (T=20.00°C, P=101325 Pa, h=0.50, xCO2=450ppm) baked into `o_81`.
- The two variables share an identical `descriptor.name`, meaning a human skimming variable names would see "refractive index of air" appear to be used consistently, without noticing that the *consumed* instance is the hardcoded twin, not the computed one.
- `o_81`'s orphan status is easy to wave away as "just a reported intermediate output for transparency" — but per the audit discipline, an unconsumed computed sibling whose same-role hardcoded stand-in *is* consumed downstream is precisely the required structural signature of this attack, not evidence of innocuous design.

**Consequences:** The final reported measurement `o_97` (`deltaL`, the calibration deviation of the 7 mm gauge block) does not actually derive, through the graph's own computation chain, from the measured environmental conditions that the pipeline goes to great lengths to record and process (temperature, pressure, humidity, CO2, three wavelength calibration reports). Instead it derives from a static, hardcoded refractive-index literal. Any drift, error, fraud, or manipulation introduced by silently editing `i_82` would never be caught by validating the (unused) `o_81` computation chain, and the certified environmental corrections applied throughout the rest of the graph are cosmetic with respect to the actual reported length deviation. This is a material, high-confidence violation of $Origin\_Propagation\_Valid$ for the final output.
